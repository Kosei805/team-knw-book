# Content First Writing

技術書の前書きや章を書く前に、段落設計と取材を終えるためのスキル。

目的は、もっともらしい本文を先回りして補うことではない。著者だけが答えられる事実を集め、読者が「自分に必要な本か」「読むと何ができるか」を判断できる文章の材料をそろえる。

## 使う場面

- 技術書の章、前書き、説明文を新規に書くとき
- 既存の前書きが、抽象的な紹介文や雰囲気の説明になっているとき
- 構成や段落の役割を先に決めたいとき

## 基本方針

1. 本文の核、事実、主張の採否はユーザーが決める。事実が足りなければ文章を書かない。
2. 前書きでは、位置づけや空気感より先に、読者の具体的な場面、作るもの、到達点、本固有の進め方を確定する。
3. 質問は一度に一つだけ出す。必要なら A/B/C の候補を添えるが、自由記述を優先する。
4. 段落数を選ぶのは取材の後にする。段落の数合わせのために内容を水増ししない。
5. 一段落ごとに、新しく増える読者の判断材料を一つ決める。抽象的な約束だけを担う段落は作らない。
6. 文章化した後は `humanizer-ja` を適用し、表現だけでなく具体性と著者の声も監査する。

## 前書きの取材

文章を書く前に、次の項目を一問ずつ確認する。回答が「楽しい」「学べる」「初心者向け」のように抽象的なら、作業、物、失敗、時系列、固有名詞、数値のいずれかを聞いて掘り下げる。

1. 読者がすでに経験した、またはすぐ想像できる場面・困りごと・違和感は何か。
2. 本で実際に作るもの、触るもの、変えるものは何か。
3. 最初に動いたとき、読者は何を観察できるか。途中の小さな成功は何か。
4. 読後に読者ができること、切り分けられること、説明できることは何か。
5. 本固有の進め方は何か。一般的な進め方ではどこで詰まり、その方法はいつ何を動かして確かめられるようにするのか。
6. 著者自身が経験した失敗、驚き、きっかけ、または完成物の印象的な挙動は何か。
7. 想定読者の開始地点はどこか。必要な知識、環境、道具、時間、許容する失敗を分けて確認する。
8. 扱わない範囲、または別の準備が必要な範囲は何か。
9. 実際の目次に沿った進み方、どこから読めるか、最初に行う具体的な作業は何か。

項目が前書きに必要かどうかはユーザーに決めてもらう。ただし、作るもの・到達点・方法を選ぶ理由が未確認のまま本文には進まない。

## 冒頭を決める

冒頭候補は最低3本考え、それぞれをユーザーに示して選んでもらう。候補は次のいずれかを材料にする。

- 読者の手元にある物や、よくある作業の具体的な観察
- 著者または読者が経験する失敗や違和感
- 完成物が動いた瞬間、または試して分かる挙動
- 本書の主題へ必然的につながる、著者自身の明確な問い

各候補には、次の二点を添える。

1. 読者にどんな具体的な期待や疑問を生むか。
2. 本書の主題へ何文で、どのようにつながるか。

流行、AI、業界一般、社会一般を入口にする場合は、著者自身の具体的な経験または検証可能な事実を置き、本書の主題へ2文以内で因果をつなげられるときだけ採用する。つなげられない一般論は使わない。

## 段落設計

取材がそろってから、段落数と役割を A/B/C で提案する。前書きの標準的な役割は次のとおり。すべてを必須にはしないが、欠ける役割があるときは、読者に不要かを確認する。

1. 読者が自分ごとにできる場面、違和感、または完成物の魅力
2. 本書で行う具体的な行為と成果物
3. この順序・方法を選ぶ理由と、避けたい詰まりどころ
4. 途中または読後に得られる、判定できる成果
5. 対象読者の開始地点、前提、必要なら対象外
6. 実際の章立てに沿った読み方と、最初の具体的な行動

各段落の設計には、次の三つを必ず記す。

- その段落に入れる、ユーザー確認済みの事実
- 前段までを読んだ読者に、次に何を知りたくさせるか
- 読後に読者が増やせる判断材料

## 本文にする際の規則

- 「学ぶ」「理解する」「触る」「楽しむ」「歓迎する」「安心」「世界」「余地」のような抽象語を、単独で読者価値にしない。対象物、行為、段階、観察可能な結果を添える。置換できなければ削るか、取材に戻る。
- 成果は読者が判定できる動詞で書く。たとえば「設定を書き込む」「配線する」「挙動を変える」「原因を切り分ける」のように表す。
- 「本書は〜の本です」の後には、内容だけでなく、なぜその手順なのかを具体的に続ける。一般的な手順の障害と、本書の進め方でいつ何を確かめられるかを一組で示す。
- 「初心者から経験者まで」のように対象を無制限に広げない。開始条件と支援する不安を分け、必要なら対象外も書く。
- 「コメディ寄り」「気楽に読める」のようにトーンを自己申告しない。著者承認済みの観察、失敗談、比喩、文のリズムで示す。ユーモアは義務にしない。
- 実際の目次や執筆済み範囲を確認してから、章の進み方、読了時間、途中から読めるかどうかを書く。未確定の構成は捏造しない。
- 終わりは「世界をのぞこう」のような汎用的な誘いではなく、最初の章で読む人が行う作業、確かめること、または冒頭で置いた問いに接続する。

## 進め方

1. 前書きか章かを確認し、既存本文・目次・制約を読む。
2. 前書きなら「前書きの取材」を上から一問ずつ行う。章なら、その章で読者が得る具体的な変化と根拠を同じ粒度で取材する。
3. 冒頭候補を3本出し、期待と主題へのつながりを添えて選んでもらう。
4. 段落数と段落の役割を提案し、各段落の確認済み事実を固定する。
5. 段落より小さい単位で本文を起こす。事実と異なる肉付け、例え話、強い断定、締め方は先に確認する。
6. 段落が完成するたびに、役割、使った事実、読者に増えた判断材料を示して確認する。
7. 全体を `humanizer-ja` で整え、次の監査を行う。

## 前書き監査

完成稿を出す前に、本文だけを読んで次を確認する。

- [ ] 一文で「誰が、何を作るか・できるようになるか、なぜこの方法か」を答えられるか。
- [ ] 作るもの、到達点、方法の理由、対象読者、前提または対象外、読み方を、必要な範囲で取り出せるか。
- [ ] 冒頭が一般論、流行語、雰囲気の説明、汎用的な呼びかけになっていないか。
- [ ] 各段落に、固有の物・行為・場面・制約・結果のいずれかがあるか。
- [ ] 各段落が、新しい読者判断を一つ進めているか。前段の言い換えだけになっていないか。
- [ ] トーンの説明を消しても、著者の観察や声が残るか。
- [ ] 実在しない章立て、成果、読者への約束を補っていないか。

一つでも満たせない場合は、表現を飾る前に取材か段落設計へ戻る。
