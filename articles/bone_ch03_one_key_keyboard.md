# キー1個のキーボードを作る

## ボタンが押されてからパソコンが反応するまでの仕組み

### キーコード

- なぜ文字そのものを送るわけではないのか
  - 「Aを入力する」と聞くと、文字の `A` をそのまま送るように見えます。
    - なぜ`A`をそのまま送ってはいけないか問題を述べる。
  - でも実際にキーボードが送るのは文字ではなく、「どのキーが押されたか」という情報です。
  - ここが曖昧なままだと、コードに出てくるキー指定がただの呪文に見えてしまいます。
- キーコードとは何か
  - キーコードは、キーごとに割り当てられた番号です。
  - パソコンはその番号を見て、「どのキーが押されたか」「どのキーが離されたか」を判断します。
  - 大文字小文字や記号も、1つの番号だけで決まるとは限りません。ほかのキーとの組み合わせまで含めて解釈されます。
- どこを見ると実感しやすいのか
  - `codes/keycode.py` の `Keycode.A = 0x04` を見せて、「Aキーには 0x04 という番号が付いている」と説明します。
  - `kbd.send(Keycode.A)` を例に出して、「文字列を送っているのではなく、Aキーの押下と解放をまとめて送っている」と読みます。
  - 余裕があれば `kbd.send(Keycode.SHIFT, Keycode.A)` に触れて、「同じAでも結果は変わる」と見せます。

### 文字ではなくキーイベントを送っている

- なぜ「1回送る」と考えるだけでは足りないのか
  - 「Aを1回送る」と「Aキーを押して離す」は、似ているようで別の話です。
  - ここを飛ばすと、長押しや複数キーの話に進んだときに急にわかりにくくなります。
- キーイベントとは何か
  - キーボードの基本動作は、押すことと離すことの2つです。
  - 1回の入力に見えるものも、内部では複数の動作の組み合わせとして扱われます。
  - 1キーキーボードの最初の例が短く書けるのは、そのまとまりを一度に扱えるからです。
- どこを見ると動きが追いやすいのか
  - `codes/keyboard.py` の `send()` が `press()` と `release_all()` を順に呼んでいるところを読みます。
  - 「今回は1回押すだけだから `send()` がちょうどいい」と位置づけます。
  - 後の章への伏線として、「細かく制御したければ `press()` と `release()` を使う」と軽く触れます。

### キーボード

- スイッチの押下をどうやって読み取ればよいのだろうか
  - キーコードがわかっても、物理ボタンをどう読めば「押された」と判断できるかは別の問題です。
  - スイッチとピンがどうつながり、なぜそのピンを入力として使うのかが見えないと、配線とコードが結び付きません。
- スイッチ入力はどういう理屈で判定されるのか
  - 今回の1キーキーボードは、スイッチ1個とマイコン1枚で作ります。
  - スイッチは入力用のピンとグラウンドの間につなぎ、ピンの電圧が高いか低いかで押下を判断します。
  - 何も押していないときの基準を先に決めておくと、押した瞬間だけ状態の変化として読めます。
- 配線とコードはどこでつながるのか
  - 配線図を1枚入れて、`GP0 - スイッチ - GND` のつながりを見せます。
  - `pin = digitalio.DigitalInOut(board.GP0)` から `pin.pull = digitalio.Pull.UP` までを、1行ずつ役割つきで読みます。
  - `if not pin.value:` のような最小例を先に出して、「押すと値が反転する」ことをシリアル表示で確かめます。

### マイコンをUSBキーボードとして振る舞わせる

- なぜ押しただけでは文字が入らないのだろうか
  - ボタンの状態が読めても、そのままではただの入力装置でしかありません。パソコンに「これはキーボードです」と名乗らないと文字は入りません。
  - ここを省くと、初期化のコードが急に現れたように見えてしまいます。
- マイコンがキーボードになる仕組みは何か
  - Raspberry Pi Pico H は、USB経由でキーボードとして振る舞えます。
  - そのための仕組みを使うと、マイコンはパソコンに対してキー入力を報告できます。
  - その上で、スイッチ入力をきっかけにキーコードを送れば、1キーキーボードになります。
- どの順で読むと全体像がつかめるのか
  - `kbd = Keyboard(usb_hid.devices)` を取り上げ、「ここでUSBキーボード役を作っている」と説明します。
  - `codes/onekey.py` 全体を「初期化」「ピン設定」「監視ループ」の3つに分けて読みます。
  - 最後に `switch.fell` で `kbd.send(Keycode.A)` を呼ぶ流れを見せて、配線とコードがつながる感覚を作ります。

## ノイズを避ける方法

### チャタリング

- なぜ1回押したのに何文字も入るのだろうか
  - スイッチは理想的に1回だけ切り替わるわけではありません。押した瞬間に細かくぶれて、1回押したのに2回3回入力されることがあります。
  - 1キーキーボードは単純だからこそ、この不具合がそのまま見えやすくなります。
- チャタリングとは何か
  - このぶれをチャタリングと呼びます。
  - 原因は、金属接点が触れた瞬間に短い時間だけON/OFFを繰り返すことです。
  - 対策の考え方は、「値を読んだ瞬間」を信用せず、少し安定するまで待つことです。
- どう直せば1回だけ反応するのか
  - チャタリングありの最小コードとして、`if not pin.value: kbd.send(Keycode.A)` の問題点を見せます。
  - そのあと `Debouncer` をかぶせて、`switch.update()` と `switch.fell` の役割を説明します。
  - `codes/onekey.py` の完成版を載せて、「押された瞬間だけ送る」形に直します。

### 入力ピンを安定させる

- なぜ押していないのに反応することがあるのだろうか
  - チャタリングとは別に、ピンがどこにもつながっていない状態だと値がふらつきます。
  - 「押していないのに反応する」原因が、スイッチではなく配線や設定にあることもここで区別したいところです。
- 入力ピンを安定させる考え方は何か
  - 入力ピンは、基準となる電位がないと高いか低いかが定まりません。
  - 何もしていないときの状態を先に固定しておく仕組みが必要です。
  - 今回の回路では、「普段は高い状態で、押すとグラウンドにつながって低くなる」という形を基本にします。
- どこを確認すると安定したと言えるのか
  - `pin.pull = digitalio.Pull.UP` を外した場合に起こる不安定さを、簡単な説明か観察メモとして入れます。
  - 「押していないときの基準を先に決める」と覚えれば、今後のマトリクス配線にもつながると示します。
  - 最後に「1キー版の完成条件」を置き、押したときだけ1回Aが入る状態を到達点にします。
