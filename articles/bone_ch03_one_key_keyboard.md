# キー1個のキーボードを作る

- 章の中心はファイル解説ではなく、データが次の形式へ変わる理由に置く
- 全体の流れを `スイッチの導通 -> GP0のHigh/Low -> 押下イベント -> Keycode.A -> HIDレポート` とする
- 各段階で、問題提起 -> 解決策 -> How（必要なコード） -> 次の問題、の順に進める
- import、一般的なPython文法、すでに説明した回路・HIDの一般論は繰り返さない
- 最後に完成版を `codes/onekey_with_debounce.py` として保存するよう案内する

## 回路を作る

- Raspberry Pi Pico H、400穴ブレッドボード、タクトスイッチ、ジャンパーワイヤーで作る
- GP0とGNDの間にスイッチを置く
- プルアップを使い、離しているときはHigh、押しているときはLowにする
- `images/one_switch.png`を参照する
- 400穴ブレッドボードの中央の溝、5穴単位の接続、タクトスイッチの4端子の向きを説明する
- スイッチを中央の溝にまたがせ、GP0側とGND側を別の接続列にする
- GP0、GND、電源ピンを取り違えないようにする
- 電源投入前に、離しているときは非導通、押したときは導通になることを確認する

## GP0の電圧を入力データへ変える

### 問題提起

- 回路ができても、プログラムはGP0を読む設定になっていない
- 入力ピンが浮くと、押していないときの値が決まらない

### 解決策

- GP0を入力にし、内部プルアップを有効にする
- 回路の状態と`pin.value`の対応表を示す

### How

- `DigitalInOut(board.GP0)`、`Direction.INPUT`、`Pull.UP`を提示する
- 値表示ループで、離しているとき`True`、押したとき`False`になることを確認する
- ここで得られるデータは「現在の状態」であり、「押下イベント」ではないと明確にする

## 現在値を押下イベントへ変える

### 問題提起

- `if not pin.value`をループに置くと、押している間ずっと処理される
- 必要なのは現在のLowではなく、HighからLowへ変化した瞬間

### 解決策

- 前回値と現在値を並べ、`True -> False`だけを押下とする
- 4通りの状態遷移表を示す

### How

- `last_state = pin.value`で初期状態を保存する
- ループ内で`current_state = pin.value`を読む
- `if last_state and not current_state`で押下を検出する
- 末尾で`last_state = current_state`へ更新する
- この段階の比較用コードを`codes/onekey_without_debounce.py`として位置付ける

## 不安定な押下を1回のイベントへ変える

### 問題提起

- 機械式スイッチは押下時にHighとLowを短時間往復する
- 前回値と現在値だけでは、チャタリングによる複数の立ち下がりを区別できない

### 解決策

- 生値と確定値を分ける
- 最後の変化から20ミリ秒以上安定した値だけを確定する
- HighからLowの確定時だけ押下イベントを作る

### How

- `last_raw_state`、`current_stable_state`、`last_changed_time`を用意する
- 生値の変化でタイマーをリセットする
- 経過時間がデバウンス時間以上になったときだけ確定する
- `_fell`をワンショットイベントとして実装する
- `update()`で観測し、`fell`でイベントを読む構成を示す
- ここまでを`codes/lib/debouncer.py`へまとめる

## 押下イベントをキーコードへ変える

### 問題提起

- `True`や`False`はAキーではない
- 文字列`"A"`を送るのではなく、キーの種類を送る必要がある

### 解決策

- `Keycode.A = 0x04`で、AキーをHIDキーコードへ対応付ける
- 0x04は文字コードではなく、Aキーを表す番号だと説明する

### How

- `codes/lib/keycode.py`のAキー定義を示す
- ShiftとAを同時に送る場合は、文字を別コードにせず、修飾キーとAの状態を組み合わせることに触れる

## キーコードをHIDレポートへ変える

### 問題提起

- キーコードを1回送るだけでは、キーを押したままになる
- 「Aを1回」は、Aを含むレポートと空のレポートの組み合わせ

### 解決策

- 押しているキーの集合を保持する
- 修飾キー、通常キー、予約領域から8バイトのレポートを作る
- キーボード用HIDデバイスへ送る

### How

- `usage_page`と`usage`でキーボード用HIDデバイスを選ぶ
- `_modifiers`、`_keys`、`_report`の順に必要なデータを導入する
- `_add_key()`で修飾キーと通常キーを分ける
- `_sync()`でレポートを作り、`send_report()`へ渡す
- `press()`で押下レポート、`release_all()`で空レポートを送り、`send()`にまとめる
- この処理を`codes/lib/keyboard.py`へまとめる

## 完成版を組み立てる

- ここまでの変換を1本の呼び出し経路にする
- `switch.update()`で観測し、`switch.fell`がTrueのときに`kbd.send(Keycode.A)`を呼ぶ
- importはここで完成版に一度だけ掲載する
- 完成版を`codes/onekey_with_debounce.py`として保存するよう指示する
- `codes/onekey_without_debounce.py`はエッジ検出とチャタリングの比較用として掲載する

## 検証

- まずGP0の値を確認する
- 次にデバウンスなし版で、前回値と現在値から1回のエッジになることを確認する
- その後デバウンスあり版で、チャタリングが1イベントにまとまることを確認する
- 最後にHIDレポートがAの押下と解放になることを確認する
- 問題があった層より後を調べず、データの変換順に戻って切り分ける
